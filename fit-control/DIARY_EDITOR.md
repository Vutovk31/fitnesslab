# Diary entry editor
prepareEntry(form, intent, {id, now, previous?}) returns operation, expectedRevision, entry, preview. Caller provides explicit action and valid full form, UUID, UTC timestamp. Decimal text supports comma/dot, not exponent, negative, thousands separators. Empty nutrient is unknown; empty quantity only for draft. Label/catalog require nonempty reference; confidence reflects source kind, not verified accuracy. Edit preserves existing status and identity; previous revision is sent unchanged to DiaryStore.update, which owns revision increment. Explicit plan/confirm actions change status; no demotion of confirmed or edit of tombstone. Preview may be null. No DB calls or mutation. Caller must populate all existing source fields on edit to retain provenance. Full UI and persistence acceptance separate. Test: npm test in fit-control with TypeScript provisioned. Current evidence is targeted local pass, not full repo build.
