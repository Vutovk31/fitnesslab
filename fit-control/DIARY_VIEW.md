# Diary read model / P0-02C preparation
Use diaryView with a list of validated diary records and explicit per-nutrient targets (positive finite numbers or null). No default personal target. Projection contains cards and five meal groups; rows carry ID/revision/date/timezone/source confidence. Confirmed is logged intake; planned is separate; forecast is both. Draft quantities can have previews but do not contribute. Null is unknown; show known subtotal plus missing count. A day with no records is not proof of no food consumed. Progress is 0..1 for visual bar; signed remainder is authoritative for exceeding target. No writes or DB calls. Read model is a dependency of future responsive UI; no DOM/UI/IndexedDB field acceptance in this slice. Use text rendering for untrusted names, show explicit error states and do not pretend missing data are zero. Actual diary UI integration awaits P0-02B acceptance.
