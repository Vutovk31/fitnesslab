# Offline speech recognition — candidate contract
Reviewed official platform documentation 2026-11-26. No actual native provider or microphone enabled.
Android: SpeechRecognizer.createOnDeviceSpeechRecognizer / isOnDeviceRecognitionAvailable (API 31+). EXTRA_PREFER_OFFLINE alone is insufficient; it may be ignored. Prefer API 33+ for checkRecognitionSupport and getInstalledOnDeviceLanguages; supported/downloadable/pending models are not equivalent to installed ones. Require ru-RU installed capability and empty remote-only path; if not verifiable (including older API or support-check errors), leave feature unavailable. Runtime RECORD_AUDIO permission, manifest service query as applicable, main-thread calls, cancel/destroy, lifecycle and device network verification required. Model downloads only as separate explicitly authorized setup, not during recognition. No generic cloud recognizer fallback.
Apple: SFSpeechRecognizer locale/availability and supportsOnDeviceRecognition plus requiresOnDeviceRecognition=true on request; a supported locale alone is not proof of offline operation. Check speech authorization, microphone permission and usage descriptions; cancel recognition task, stop audio engine and remove audio tap on lifecycle/permission loss. Evaluate newer SpeechAnalyzer/SpeechTranscriber/DictationTranscriber as alternate on supported OS/hardware, check installedLocales vs supportedLocales; no automatic download or language substitution. Actual Russian-language availability is device dependent; no claim that all iPhones support it.

## Local synthetic controller
Provider synthetic=true, check({locale:'ru-RU',offlineOnly:true,signal}) returns exactly available/offline/locale; recognize(same request) returns exactly text/locale/offline/final. Strict boolean and locale checks, 8000 UTF-16 code units, nonempty/control-character validation. Explicit approval before any call; foreground required. 120s shared timeout for check+recognition, AbortSignal and generation invalidation; block repeat until provider settles even after abort. Review state only; accept(true) releases text once to caller for existing manual transcript editor, no actual UI wiring or diary write. Clear on cancel/background/disposal. Provider offline/synthetic flags are contract assertions, not trusted hardware attestation; controller alone cannot constrain arbitrary provider network traffic. Provider must implement bounded native teardown and settlement; ignored cancellation may leave session blocked until provider settles. No actual audio passed, network API, persistence or cloud fallback in module.
Native acceptance: airplane-mode Russian speech, absent/unsupported models, permission denial/revocation, real lifecycle, repeated start/cancel, timeout and resources, network monitoring and no server fallback. Verify provider identity/config and real data privacy gate before enablement. Existing manual path remains available.
