# Native privacy release gate
Status: BLOCKED FOR PERSONAL DATA. 2026-11-26.
Default build mode blocked. Only FIT_CONTROL_SYNTHETIC_BUILD=1 compiles acceptance-only mode. Explicit approval before database access; separate fit_control_synthetic_v1 database; existing fit_control_diary_v1 not touched by this startup. File port stripped in synthetic bootstrap. CSP denies web connections and form submission; native bridge and OS behavior still require testing. Approval is a warning/consent for synthetic tests, not proof that typed input is synthetic and not authorization for health data.
## Threats and candidate mitigation
- Lost/unlocked device or extracted app files: app-private storage plus SQLCipher candidate; verify DB/WAL/journal/temp files, no plaintext fallback, OS screen lock/access policy.
- Key disclosure: random per-install secret generated with OS CSPRNG, wrapped/stored using platform Keychain/Keystore-backed facility; do not embed in JS bundle, git, logs, environment files or remote service. Assess plugin secret storage implementation and bridge memory exposure before acceptance; use a native-only key adapter if required.
- Missing key with existing encrypted database: fail closed; no regenerate/clear/delete/decrypt automatically. Recovery only via explicit user-approved encrypted portable backup or authenticated recovery mechanism. Separate first-install from existing DB and key-loss states. No conversion of legacy test DB into real-data DB. Key rotation requires verified backup, non-destructive transactional plan and fault tests before implementation.
- Unencrypted exports and OS cloud backups: disable file port until authenticated encrypted portable envelope and local destination contract implemented and device tested. Exclude sensitive DB and secret material from Android auto-backup/data extraction and iOS backup as appropriate; verify generated native config, not just web settings. No cloud upload or sharing without specific consent.
- UI/diagnostics: sanitize errors, no analytics payload, no remote webview content; verify CSP in actual WebView, plugin native networking, screenshots/app-switcher exposure, clipboard, logs, crash reports and no unexpected permissions.

Source https://github.com/capacitor-community/sqlite/blob/v8.1.1/src/definitions.ts exposes these methods and change/clear/check secrets. These are candidate APIs, not validated key lifecycle/security. Do not copy documentation's example passphrase or enable existing-database conversion. Current config remains encryption=false for synthetic mode only.
## Mandatory acceptance before real-data enablement
Actual native build, app-private DB and encrypted-file verification on both OSes; restart, correct/wrong/missing key, failed provisioning, no plaintext fallback, key loss/restore, uninstall/reinstall and OS backup policy tests. Inspect actual package/network/permissions; verify encrypted portable backup tamper/wrong passphrase/rollback, bounded memory, file cancellation and local save. Owner approves privacy and recovery UX. No production switch currently exists. No automatic rollout.
