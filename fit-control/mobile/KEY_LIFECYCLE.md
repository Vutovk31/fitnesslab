## Decision contract
Inputs are seven finite enums from a future trusted native observer: platform, policy, installation, namespace, database, key, probe. No raw secret or arbitrary metadata. A verified policy input is an assumption of the model, not attestation. Native observer must independently establish namespace/file/sidecar absence, installation marker, key state (including inaccessible vs absent), encryption and successful read-only existing DB probe. No side-effectful existence check; no secrets crossing JS bridge. Unverified/inconsistent/unknown state fails closed.
- Fresh marker + empty namespace + absent DB and key + no probe + explicit approval: provision_candidate.
- Ready marker + isolated namespace + encrypted DB + present key + no probe: verify_candidate.
- Same established state + successful probe: open_candidate.
- All other states blocked. Candidate outcomes authorize no actual action in current build.
## Future native implementation gates
Use isolated per-install key and DB namespace with exclusive native lock. Verify observations again inside lock before any operation; durable marker before provisioning; interruption must never silently retry, clear keys, recreate DB, or downgrade to plaintext. Never infer key absence from an exception, inaccessible Keychain or absent DB alone. If key exists without DB, or encrypted DB without key, block. Explicit recovery via validated encrypted portable backup to a separately authorized empty destination only. No destructive rotation/migration without independently verified recovery path. Determine provider-specific secret generation, persistence and read-only cipher verification on-device before connecting any real-data path.
Android: verify actual merged manifest and backup rules, exclude DB/sidecars, secret preferences and provisioning markers from cloud/device transfer and relevant platform versions, including cross-platform transfer where applicable. Verify Keystore key policy and no plaintext diagnostics. iOS: explicitly choose device-bound accessibility and data protection appropriate to foreground use; exclude DB/sidecars and markers from backup with verified resource attributes; verify Keychain migration behavior and lock/unlock. Both: test reinstall/restore/device lock, wrong/missing/locked key, interrupted provisioning, no database overwrite or loss, native file/backup protection and evidence before release.
The decision module is not imported by native bootstrap. It performs no I/O, creates no secret, provides no encryption at rest and cannot establish trusted policy by itself. Existing synthetic-only bootstrap and disabled file/passphrase ports unchanged.
