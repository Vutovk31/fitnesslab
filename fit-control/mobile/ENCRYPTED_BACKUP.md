# Encrypted portable backup v1 — candidate contract
Binary envelope (Uint8Array), not JSON or base64:
offset 0..3 ASCII FCBK, 4 version 1, 5..20 random 128-bit salt, 21..32 random 96-bit nonce, 33..end AES-256-GCM ciphertext and final 128-bit tag. All 33 header bytes are additional authenticated data. Version fixes PBKDF2-HMAC-SHA256, 600000 iterations, 256-bit nonextractable key; no attacker-supplied algorithm/iteration parameters. Overhead 49 bytes; max envelope 16 MiB + 49 bytes, inner JSON obeys existing v1/v2/v3 validation and limits. No plaintext fallback. Passphrase 12+ Unicode code points and <=1024 UTF-8 bytes; exact Unicode, no trim or normalization, malformed surrogate rejected. Length is not entropy; recommend unique high-entropy passphrase, lost password means no recovery. No passphrase persistence, network, or native file write. Best-effort zeroization of byte arrays; JavaScript strings and runtime/internal key buffers cannot be guaranteed erased. Full text/cipher in memory, not streaming.
Rationale: WebCrypto native primitive rather than custom cipher; OWASP Password Storage Cheat Sheet recommends 600000 iterations for PBKDF2-HMAC-SHA256 (reference for work factor, not certification of this backup scheme): https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html ; AES-GCM nonce and AAD guidance https://developer.mozilla.org/en-US/docs/Web/API/AesGcmParams . Reviewed 2026-11-26.
Consumer: explicitly decrypt, validate, obtain user confirmation and invoke existing atomic empty-target restore. Do not retain plaintext on filesystem. File bridge, secure passphrase UI, export cancellation, mobile WebCrypto availability and heap/KDF timing, native key provisioning and backup exclusion are pending. Real-data gate remains blocked. No downgrade of encrypted format; legacy plaintext imports remain separate test APIs and are not exposed via native file flow.
